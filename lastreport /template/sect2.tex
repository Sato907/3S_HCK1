\subsubsection{概要}
まず，指揮デバイスについて説明する．指揮デバイスのシステム構成図を図\ref{fig:sys_siki}に示す．本デバイスは，演奏全体を統括するデバイスであり，主に以下の３つの機能を有する．

第一の機能は，演奏開始トリガーの送信である．本機能の設計について図\ref{fig:inta_kaisi}に示す．ユーザが指揮デバイスに搭載されたタクトスイッチを押下すると，中継機デバイスと楽器デバイスへ演奏開始トリガーを送信する．さらに，中継機デバイスの回転が開始される．

第二の機能は，楽曲のBPM変更である．本機能の設計について図\ref{fig:inta_siki}に示す．ユーザがスライド式可変抵抗器を操作した後，デバイスを振ると新しい設定BPM情報が中継機デバイスへ送信される．これにより，中継機デバイスのモータ回転速度がこの値に追従して変化する．そして，その回転に伴うレーザーの通過光を介して各楽器デバイスに情報が伝達され，BPMの変更される．また，楽曲のBPMは5段階に分けて変更できる．

第三の機能は，楽曲の音量変更である．本機能の設計について図\ref{fig:inta_siki2}に示す．ユーザがスライド式可変抵抗器を操作した後，デバイスを振ると音量情報が各楽器デバイスへマルチキャスト送信されることで，音量が変更される．また，BPMと同様に音量も5段階に分けて変更できる．ここからは，外部設計と内部設計について説明をする．

\subsubsection{外部設計}
本節では指揮デバイスの外部設計について説明する．まず，本デバイスを構成する部品について表\ref{table:siki}に示す．デジタル3軸加速度センサは指揮デバイスの動きの検知に使用し，スライド式可変抵抗器はBPMおよび音量変更に使用される．
当初はデバイスの電力供給源として$\SI{9}{V}$のアルカリ電池を外部電源として使用することを検討していたが，電池なしでも正常動作が確認できたため，軽量化のためPCとのUSB接続から電力を供給するように変更した．Arduino内蔵の電圧レギュレータにより$\SI{5}{V}$および$\SI{3.3}{V}$ を生成し，各モジュールへ安定した電力を供給する．
また，指揮デバイスの回路図を図\ref{fig:kairo_siki} に示す．加速度センサにはGY-291（ADXL345）を用いており，I2C通信によりArduinoと接続する．CSピンをArduinoの$\SI{3.3}{V}$に接続することでI2Cモードに設定し，さらに SDOピンをGNDに接続することでI2Cアドレスを0x53に固定している．また，SDAピンおよびSCLピンはそれぞれデータ通信線およびクロック信号線としてArduinoのA4，A5ピンに接続している．加えて，加速度が内部設定した閾値を超過した場合には，INT1 ピンから Arduino の D2 ピンへ割り込み信号が出力される．
これにより，指揮デバイスの振り動作を検知し，モータ制御用 Arduino との UDP 通信を開始する．

さらに，演奏開始および終了信号の送信に用いるボタン入力判定回路を実装する．ボタンの誤判定を防止するため10k$\Omega$のプルアップ抵抗を用いた回路を構成する．
ボタンが押されていない状態では，入力ピン D3 はプルアップ抵抗を介して 5 V に接続されるため HIGH 状態となる．
一方，ボタン押下時には回路が GND に短絡され，入力電位が LOW に遷移する．指揮デバイスのプログラムでは D3 ピンの状態変化を常時監視することで，
演奏開始および終了操作を判定する．

\texttt{button}関数はこの1関数のみで構成されるため，以下では処理の流れに沿って実際のコードを2箇所に分けて説明する．まず，立下りエッジの検知部分について説明する．\texttt{switch\_status}に現在のピン状態を読み込み，前回値\texttt{before\_switch\_status}と比較することで，HIGH→LOWへ変化した瞬間（ボタンが押された瞬間）のみを検知する．該当部分をコード\ref{lst:btn_edge}に示す．

\begin{lstlisting}[caption={button関数（立下りエッジの検知部分）}, label={lst:btn_edge}]
    switch_status = digitalRead(input_PIN);
    if (switch_status == 0 && before_switch_status == 1) {
        ...
    }
    before_switch_status = switch_status;
\end{lstlisting}

次に，立下りを検知した際の状態トグルと送信処理について説明する．\texttt{isButtonPlaying}がtrue（演奏中）であればsync.\texttt{sendEnd}()を呼び出して演奏を終了し，false（停止中）であれば現在のBPM段階（pot.\texttt{getBpmStep}()）を引数としてsync.\texttt{sendStart}()を呼び出して演奏を開始する．いずれの場合も\texttt{isButtonPlaying}の値を反転させたうえで，delay(300)により300 ms待機することでチャタリングを防止する．該当部分をコード\ref{lst:btn_send}に示す．

\begin{lstlisting}[caption={button関数（状態トグルと送信処理部分）}, label={lst:btn_send}]
    if (isButtonPlaying) {
        sync.sendEnd();
        isButtonPlaying = false;
    } else {
        uint8_t step = pot.getBpmStep();
        sync.sendStart(step);
        isButtonPlaying = true;
    }
    delay(300); // チャタリング防止
\end{lstlisting}

なお，\texttt{sendStart}・\texttt{sendEnd}の内部では，\texttt{SyncManager}クラスが複数台のデバイスへラウンドロビン方式による冗長送信を行っている．この通信処理の詳細な実装は付録に示すプログラム全文を参照されたい．

次に，指揮デバイスにおける加速度センサの制御処理について説明する．指揮デバイスは，加速度センサを用いてユーザが指揮棒を振ったことを検知し，演奏情報の更新を行う．センサ値の急激な変化を読み取ることで動作を判定し，誤検知防止機能を設けることで安定した動作を実現している．処理の流れは，差分算出と判定，多重検知の防止，状態の反転，事後処理の4段階に大別される．まず差分算出と判定では，現在の合成加速度\texttt{currentAccVal}と前回値\texttt{lastAccVal}との差の絶対値を求める．この差分が検知閾値\texttt{accThreshold}を超過し，かつ前回検知から\texttt{shakeInterval}以上の時間が経過している場合に，指揮棒を振ったと判定する．多重検知の防止では，一度振る動作を検知すると\texttt{lastDetectTime}を現在時刻に更新し，以降\texttt{shakeInterval}が経過するまでは加速度の変化を無視することで，一連の動作による複数回の誤検知を防止する．状態の反転では，振る動作を検知するたびに\texttt{isStarted}のbool値を反転させる．事後処理として，次回の判定に備えて\texttt{currentAccVal}の値を\texttt{lastAccVal}へ代入し，前回のサンプリング時刻を更新する．また，振る動作の確定時には，可変抵抗器側で設定値の変更を検知したフラグ\texttt{bpmFrag}または\texttt{volFrag}（\ref{sec:pot_detail}項で説明する）が有効になっている場合，\texttt{SyncManager}クラスを介してその情報の送信指示を行う．さらに，I2C通信の異常を検知した場合には自動復旧を行う機能を備えている．加速度センサの制御で使用する変数の仕様を表\ref{table:siki_acc_var}に示す．

以下では，表\ref{table:siki_acc_func}に示した順に，各関数の処理内容を実際のコードとともに説明する．はじめに，\texttt{setupADXL345}関数について説明する．この関数は，Wire.beginによるI2C通信の開始後，ADXL345のPOWER\_CTLレジスタにMeasureビットを書き込むことでセンサを測定モードへ移行させ，DATA\_FORMATレジスタを初期値のまま設定する．\texttt{setupADXL345}関数をコード\ref{lst:acc_setup}に示す．

\begin{lstlisting}[caption={AccManager::setupADXL345関数}, label={lst:acc_setup}]
void AccManager::setupADXL345() {
  Wire.begin();

  Wire.beginTransmission(ADXL345_ADDR);
  Wire.write(REG_POWER_CTL);
  Wire.write(0x08); // Measure bit ON
  Wire.endTransmission();

  Wire.beginTransmission(ADXL345_ADDR);
  Wire.write(REG_DATA_FORMAT);
  Wire.write(0x00);
  Wire.endTransmission();

  lastAccVal = readAccMagnitude();
}
\end{lstlisting}

次に，加速度の実測値を取得する\texttt{readAccMagnitude}関数について説明する．この関数は，DATAX0レジスタから連続する6バイト（X, Y, Z軸それぞれ2バイトの符号付き整数）をrequestFromで読み出し，3軸のベクトル合成値（合成加速度）を平方根の計算により求めて返り値とする．\texttt{readAccMagnitude}関数をコード\ref{lst:acc_read}に示す．

\begin{lstlisting}[caption={AccManager::readAccMagnitude関数}, label={lst:acc_read}]
float AccManager::readAccMagnitude() {
  Wire.beginTransmission(ADXL345_ADDR);
  Wire.write(REG_DATAX0);
  if (Wire.endTransmission(false) != 0) {
    recoverI2C();
    return lastAccVal;
  }

  uint8_t n = Wire.requestFrom(ADXL345_ADDR, (uint8_t)6, (uint8_t)true);
  if (n < 6) {
    recoverI2C();
    return lastAccVal;
  }

  int16_t rawX = (int16_t)((Wire.read()) | (Wire.read() << 8));
  int16_t rawY = (int16_t)((Wire.read()) | (Wire.read() << 8));
  int16_t rawZ = (int16_t)((Wire.read()) | (Wire.read() << 8));

  return sqrtf((float)rawX*rawX + (float)rawY*rawY + (float)rawZ*rawZ);
}
\end{lstlisting}

ここで，Wire.endTransmission(false)がエラーを返した場合，またはrequestFromで6バイト読み出せなかった場合には，I2Cバスがロックアップ（スレーブがSDA線を握ったまま停止する現象）していると判断し，\texttt{recoverI2C}関数を呼び出したうえで前回値\texttt{lastAccVal}を返すことで，誤ったシェイク検知（ニセshake）を防いでいる．続いて，\texttt{recoverI2C}関数について説明する．この関数は，SCL線を9回手動でトグルさせてSDA線の握りを解放したうえでSTOP条件を生成し，Wireを再初期化してADXL345を再設定することでバスを復旧させる．\texttt{lastRecoverMs}は，この復旧処理およびログ出力が短時間に連続して実行されることを防ぐスロットル用の時刻管理に用いられる．\texttt{recoverI2C}関数をコード\ref{lst:acc_recover}に示す．

\begin{lstlisting}[caption={AccManager::recoverI2C関数}, label={lst:acc_recover}]
void AccManager::recoverI2C() {
  unsigned long now = millis();
  if (now - lastRecoverMs >= 1000) {   // ログのスロットル
    lastRecoverMs = now;
  }

  Wire.end();

  // バスクリア: SCLを9クロック叩いて握られたSDAを解放
  pinMode(SDA, INPUT_PULLUP);
  pinMode(SCL, OUTPUT);
  for (int i = 0; i < 9; i++) {
    digitalWrite(SCL, LOW);  delayMicroseconds(5);
    digitalWrite(SCL, HIGH); delayMicroseconds(5);
  }
  // STOP条件 (SDA: LOW→HIGH while SCL HIGH)
  pinMode(SDA, OUTPUT);
  digitalWrite(SDA, LOW);  delayMicroseconds(5);
  digitalWrite(SCL, HIGH); delayMicroseconds(5);
  digitalWrite(SDA, HIGH); delayMicroseconds(5);

  // Wire再初期化＆センサ再設定
  Wire.begin();
  Wire.beginTransmission(ADXL345_ADDR);
  Wire.write(REG_POWER_CTL);   Wire.write(0x08);
  Wire.endTransmission();
  Wire.beginTransmission(ADXL345_ADDR);
  Wire.write(REG_DATA_FORMAT); Wire.write(0x00);
  Wire.endTransmission();
}
\end{lstlisting}

次に，update関数について説明する．この関数はloop内で毎回呼び出され，\texttt{ACC\_SAMPLE\_INTERVAL}（20 ms）ごとに加速度の実測値を取得し，前回値との差diffを求める．diffが検知閾値\texttt{accThreshold}を超過し，かつ前回検知から\texttt{shakeInterval}（750 ms，多重検知防止用）が経過している場合にのみ，振り動作として検知し\texttt{updateShakedInfo}関数を呼び出す．update関数をコード\ref{lst:acc_update}に示す．

\begin{lstlisting}[caption={AccManager::update関数}, label={lst:acc_update}]
void AccManager::update(SyncManager& sync, PotManager& pot) {
  unsigned long now = millis();
  if (now - lastSampleTime >= ACC_SAMPLE_INTERVAL) {
    lastSampleTime = now;
    currentAccVal = readAccMagnitude();
    float diff = fabsf(currentAccVal - lastAccVal);

    bool overThreshold  = (diff > accThreshold);
    bool intervalPassed = ((now - lastDetectTime) >= shakeInterval);

    if (overThreshold && intervalPassed) {
      lastDetectTime = now;
      isStarted = !isStarted;
      updateShakedInfo(sync, pot);
    }
    lastAccVal = currentAccVal;
  }
}
\end{lstlisting}

最後に，\texttt{updateShakedInfo}関数について説明する．この関数は，振り動作の検知をトリガとして，\texttt{PotManager}が保持する\texttt{bpmFrag}・\texttt{volFrag}フラグ（可変抵抗器の値が変化した場合に立つフラグ．\ref{sec:pot_detail}項で説明する）を確認し，フラグが立っている項目についてのみ\texttt{SyncManager}経由でBPMまたは音量の変更情報を送信する．すなわち，実際に無線送信が発生するのは，可変抵抗器を操作した後にデバイスを振った場合に限られる．\texttt{updateShakedInfo}関数をコード\ref{lst:acc_shaked}に示す．

\begin{lstlisting}[caption={AccManager::updateShakedInfo関数}, label={lst:acc_shaked}]
void AccManager::updateShakedInfo(SyncManager& sync, PotManager& pot) {
  if (pot.bpmFrag) {
    sync.sendBPM(pot.getBpmStep());
    pot.bpmFrag = false;
  }
  if (pot.volFrag) {
    sync.sendVolume(pot.getVolStep());
    pot.volFrag = false;
  }
}
\end{lstlisting}

最後に，指揮デバイスにおける可変抵抗器を用いたBPM・音量読み取り機能について説明する．指揮デバイスでは，演奏の要素であるBPMと音量を，ユーザが操作できるように可変抵抗器を用いて5段階で調整する．アナログ入力値の特性を考慮したデータ処理を行うことで，安定した制御環境を構築している．アルゴリズムは，サンプリングと移動平均化，範囲分割，パラメータの抽出と出力の3段階に分けられる．サンプリングと移動平均化では，\texttt{SAMPLE\_INTERVAL}ごとにBPMおよび音量変更用の可変抵抗器の電圧値を，配列\texttt{bpmSamples}・\texttt{volSamples}に\texttt{sampleSize}分だけ読み取り保存する．このとき，配列の各要素は書き込み位置（\texttt{bpmReadIndex}・\texttt{volReadIndex}）が指す最も古い値から順に上書きされ，上書きの直前に該当要素の値を合計\texttt{bpmTotal}・\texttt{volTotal}からあらかじめ減算し，新たに読み取った値を加算することで，配列全体を読み直すことなく常に最新の合計値を保持する（移動合計）．配列が一巡し全要素が新しい値に更新された時点（\texttt{bpmBufferFull}・\texttt{volBufferFull}がtrueになった時点）以降，この合計値を\texttt{sampleSize}で除算した移動平均値を\texttt{averageBpmVal}・\texttt{averageVolVal}に格納する．範囲分割では，移動平均化された値を\texttt{STEP\_BOUNDARIES}[]で定義した4つの閾値と比較し，1〜5の段階番号を\texttt{currentBpmStep}・\texttt{currentVolStep}に格納する．パラメータの抽出と出力では，算出した段階が直前の段階（\texttt{prevBpmStep}・\texttt{prevVolStep}）から変化した場合にのみ，公開フラグ\texttt{bpmFrag}・\texttt{volFrag}を立てる．外部からは\texttt{getBpmStep}()・\texttt{getVolStep}()を介して現在の段階を取得し，前述の加速度センサ制御における棒振り動作の確定時にこれらのフラグを参照して各楽器機への送信を行う．なお，音量用可変抵抗器は配線の都合上，回した方向とセンサ値の増減が逆になるため，\texttt{getVolStep}()は6-\texttt{currentVolStep}を返すことで表示上の段階を反転させる．BPM・音量読み取り機能で使用する変数の仕様を表\ref{table:siki_pot_var}に示す．

void PotManager::update() {
  unsigned long now = micros();

次に，\texttt{bpmUpdatePotentiometers}関数について説明する．この関数は，リングバッファ（配列\texttt{bpmSamples}，添字\texttt{bpmReadIndex}）を用いた移動平均処理により，analogReadで取得したアナログ値のノイズを平滑化する．具体的には，配列の最も古いサンプルを合計値\texttt{bpmTotal}から減算し，新たに取得した値を加算したうえで書き込み位置を進める．\texttt{sampleSize}（10サンプル）分のバッファが一巡した時点から，合計値をサンプル数で割った移動平均\texttt{averageBpmVal}を算出し，\texttt{calcStep}関数で段階へ変換したうえで，前回段階から変化していればtrueを返す．\texttt{bpmUpdatePotentiometers}関数をコード\ref{lst:pot_bpm}に示す．

\begin{lstlisting}[caption={PotManager::bpmUpdatePotentiometers関数}, label={lst:pot_bpm}]
bool PotManager::bpmUpdatePotentiometers() {
  bpmTotal -= bpmSamples[bpmReadIndex];
  bpmSamples[bpmReadIndex] = analogRead(PIN_BPM);
  bpmTotal += bpmSamples[bpmReadIndex];
  bpmReadIndex = (bpmReadIndex + 1) % sampleSize;
  if (bpmReadIndex == 0) bpmBufferFull = true;
  if (!bpmBufferFull) return false;

  averageBpmVal = (float)bpmTotal / sampleSize;
  currentBpmStep = calcStep(averageBpmVal);

  if (currentBpmStep != prevBpmStep) {
    prevBpmStep = currentBpmStep;
    return true;
  }
  return false;
}
\end{lstlisting}

続いて，\texttt{calcStep}関数について説明する．この関数は，\texttt{bpmUpdatePotentiometers}関数および\texttt{volUpdatePotentiometers}関数から呼び出され，得られた移動平均値を1〜5の5段階に離散化する．\texttt{STEP\_BOUNDARIES}配列（300, 500, 650, 818）に対する大小比較によって段階を決定しており，境界値の間隔を均等にしていない理由は，可変抵抗器の実測特性に合わせて各段階の操作しやすさを調整しているためである．\texttt{calcStep}関数をコード\ref{lst:pot_calc}に示す．

\begin{lstlisting}[caption={PotManager::calcStep関数}, label={lst:pot_calc}]
int PotManager::calcStep(float val) {
  if      (val <= STEP_BOUNDARIES[0]) return 1;
  else if (val <= STEP_BOUNDARIES[1]) return 2;
  else if (val <= STEP_BOUNDARIES[2]) return 3;
  else if (val <= STEP_BOUNDARIES[3]) return 4;
  else                                return 5;
}
\end{lstlisting}

次に，\texttt{volUpdatePotentiometers}関数について説明する．この関数は\texttt{bpmUpdatePotentiometers}関数と同様の移動平均処理を行うが，対象のピンおよび内部変数が音量用（\texttt{PIN\_VOL}，\texttt{volSamples}等）に置き換わっている点のみが異なり，処理の骨格は共通している．\texttt{volUpdatePotentiometers}関数をコード\ref{lst:pot_vol}に示す．

\begin{lstlisting}[caption={PotManager::volUpdatePotentiometers関数}, label={lst:pot_vol}]
bool PotManager::volUpdatePotentiometers() {
  volTotal -= volSamples[volReadIndex];
  volSamples[volReadIndex] = analogRead(PIN_VOL);
  volTotal += volSamples[volReadIndex];
  volReadIndex = (volReadIndex + 1) % sampleSize;
  if (volReadIndex == 0) volBufferFull = true;
  if (!volBufferFull) return false;

  averageVolVal = (float)volTotal / sampleSize;
  currentVolStep = calcStep(averageVolVal);

  if (currentVolStep != prevVolStep) {
    prevVolStep = currentVolStep;
    return true;
  }
  return false;
}
\end{lstlisting}

最後に，\texttt{getBpmStep}関数および\texttt{getVolStep}関数について説明する．いずれも\texttt{PotManager.h}内でインライン定義されたゲッター関数であり，外部（\texttt{AccManager}クラス）から現在の段階番号を取得するために用いられる．\texttt{getVolStep}関数では，可変抵抗器を回転させる向きと，音量として直感的に理解しやすい段階の増減方向を一致させるため，\texttt{6 - currentVolStep}という変換を行っている点が\texttt{getBpmStep}関数と異なる．両関数をコード\ref{lst:pot_getters}に示す．

\begin{lstlisting}[caption={PotManager::getBpmStep関数・getVolStep関数}, label={lst:pot_getters}]
uint8_t getBpmStep() const { return currentBpmStep; }
uint8_t getVolStep() const { return 6 - currentVolStep; }
\end{lstlisting}

\texttt{FerrisWheel.ino}のloop関数は，Udp.parsePacket()でパケットの到着を監視し，届いていればuint8\_t \texttt{packetBuffer}[10]として2バイト分を読み取る．先頭バイト\texttt{packetBuffer}[0]をヘッダ文字として判定し，ヘッダが'S'（演奏開始）の場合はmotor.\texttt{startRamp}()と\texttt{displayBPM}()を，'B'（BPM変更）の場合はmotor.\texttt{changeBPM}()と\texttt{displayBPM}()を，'E'（演奏終了）の場合はmotor.\texttt{stopRamp}()と\texttt{clearDisplay}()を，2バイト目のペイロード（BPM段階番号）を引数として呼び出す構成となっている．loop関数をコード\ref{lst:kan_loop}に示す．

\begin{lstlisting}[caption={FerrisWheel.inoのloop関数}, label={lst:kan_loop}]
void loop() {
    uint8_t packetSize = Udp.parsePacket();
    if (packetSize <= 0) return;
    if (packetSize != 2) {
        while (Udp.available()) Udp.read();
        return;
    }

    Udp.read(packetBuffer, sizeof(packetBuffer));
    char    header  = packetBuffer[0];
    uint8_t payload = packetBuffer[1];

    switch (header) {
        case 'S':
            running = true;
            motor.startRamp(payload);
            displayBPM(payload);
            break;
        case 'B':
            if (!running) break;
            motor.changeBPM(payload);
            displayBPM(payload);
            break;
        case 'E':
            running = false;
            motor.stopRamp();
            clearDisplay();
            break;
    }
}
\end{lstlisting}

まず，中継機デバイスにおけるモータの制御処理について説明する．本デバイスのギアボックスモータの回転速度を制御するために，ArduinoのPWM(パルス幅変調)機能を用いてモータの平均印加電圧を制御する．
PWMとは，デジタル出力ピンから出力される短形波のHIGH状態とLOW状態の時間比率(デューティー比)を変化させることで，擬似的にアナログ電圧を生成する制御方式である．Arduinoのデジタル出力ピンは$\SI{5}{V}$のHIGHか$\SI{0}{V}$のLOWのいずれかしか出力できないが，HIGHとLOWを高速に切り替えてデューティー比を調整することで，負荷に対して見かけ上の連続的な電圧を印加することが可能となる．

本デバイスは，ArduinoのD5ピンをモータドライバーモジュールに接続し，PWM制御を行う構成としている．ArduinoのanalogWrite関数は，引数として0から255の整数値を受け取り，この値に応じたデューティー比の短形波を出力する．このとき引数が0のときデューティー比は常時LOWであり，255のときデューティー比は常時HIGHとなる．中間値では，引数に比例したデューティー比の短形波が生成される．
この関係を式で表すと，供給電圧を $V_{cc}$（定数 \texttt{VCC}），プログラム上の出力値を $pwmValue$ とすると，モータに加わる平均電圧 $V_{average}$ は(\ref{eq:average})式で決定される．

\begin{equation}
    \label{eq:average}
    V_{average} = V_{cc} \times \frac{pwmValue}{255}
\end{equation}

このとき，モータの巻線が持つインダクタンスとギアボックスの機械的慣性が電気的・機械的なローパスフィルタとして機能するため，モータはパルスの平均値に応じた一定速度で滑らかに回転する．

次に，ルックアップテーブルによる速度制御について説明する．一般的なDCモータの回転速度は供給電圧に比例する性質があるが\cite{ref:control}，実際には摩擦や機構の負荷などによる非線形な挙動を示す事が多い．
そのため，当初検討していた「4拍で90度（1小節が90度）回転する」といった幾何学的な理論式による制御ではなく，より確実な速度追従を実現するため，幾何学的な縛りを廃止して実測値に基づくルックアップテーブル方式を採用する．

    \texttt{changeBPM} & \texttt{void} & \texttt{uint8\_t stepNumber} & 演奏中のBPM変更を行う．\texttt{startRamp}とは異なり，段階的な加減速を行わず目標の\texttt{pwmValue}を即座に出力する\\

    \hline
    \texttt{updateStatus} & \texttt{void} & なし & \texttt{RPM}から角速度\texttt{omega}を，\texttt{pwmValue}から平均電圧\texttt{V\_average}を算出する\\

\begin{lstlisting}[caption={MotorControl::begin関数}, label={lst:motor_begin}]
void MotorControl::begin() {
    pinMode(PIN_MOTOR_PWM, OUTPUT);
    analogWrite(PIN_MOTOR_PWM, 0);
}
\end{lstlisting}

次に，\texttt{createRpmTable}関数について説明する．この関数もsetup内で一度だけ呼び出され，\texttt{bpmTable}の各要素を16で除算することで\texttt{rpmTable}を生成する．\texttt{createRpmTable}関数をコード\ref{lst:motor_createrpm}に示す．

\begin{lstlisting}[caption={MotorControl::createRpmTable関数}, label={lst:motor_createrpm}]
void MotorControl::createRpmTable() {
    for (uint8_t i = 0; i < 5; i++) {
        rpmTable[i] = bpmTable[i] / 16.0f;
    }
}
\end{lstlisting}

次に，\texttt{startRamp}関数について説明する．この関数は，まず\texttt{stepToNumber}関数によって目標の\texttt{pwmValue}を求めたうえで，出力値を0から\texttt{pwmValue}まで5刻みで増加させながら40 msずつ待機することで，モータを滑らかに加速させる．\texttt{startRamp}関数をコード\ref{lst:motor_startramp}に示す．

\begin{lstlisting}[caption={MotorControl::startRamp関数}, label={lst:motor_startramp}]
void MotorControl::startRamp(uint8_t stepNumber) {
    stepToNumber(stepNumber);
    for (int i = 0; i <= pwmValue; i += 5) {
        analogWrite(PIN_MOTOR_PWM, i);
        delay(40);
    }
    analogWrite(PIN_MOTOR_PWM, pwmValue);
}
\end{lstlisting}

次に，\texttt{stopRamp}関数について説明する．この関数は\texttt{startRamp}関数と対になる処理であり，現在の\texttt{pwmValue}から0まで5刻みで減少させながら40 msずつ待機することで，モータを滑らかに減速・停止させる．\texttt{stopRamp}関数をコード\ref{lst:motor_stopramp}に示す．

\begin{lstlisting}[caption={MotorControl::stopRamp関数}, label={lst:motor_stopramp}]
void MotorControl::stopRamp() {
    for (int i = pwmValue; i >= 0; i -= 5) {
        analogWrite(PIN_MOTOR_PWM, i);
        delay(40);
    }
    analogWrite(PIN_MOTOR_PWM, 0);
}
\end{lstlisting}

次に，\texttt{changeBPM}関数について説明する．この関数は演奏中にBPMの段階が変更された際に呼び出され，\texttt{stepToNumber}関数と\texttt{updateStatus}関数によって新しい段階の値を求めたうえで，\texttt{startRamp}関数のような段階的な加減速を行わず，目標の\texttt{pwmValue}を即座に出力する．演奏を止めずにテンポを追従させるため，段階的な加減速は行わない仕様としている．\texttt{changeBPM}関数をコード\ref{lst:motor_changebpm}に示す．

\begin{lstlisting}[caption={MotorControl::changeBPM関数}, label={lst:motor_changebpm}]
void MotorControl::changeBPM(uint8_t stepNumber) {
    stepToNumber(stepNumber);
    updateStatus();
    analogWrite(PIN_MOTOR_PWM, pwmValue);
}
\end{lstlisting}

最後に，\texttt{stepToNumber}関数と\texttt{updateStatus}関数について説明する．\texttt{stepToNumber}関数は，受信した段階番号(1〜5)が範囲内であることを確認したうえで，\texttt{bpmTable}・\texttt{pwmTable}・\texttt{rpmTable}の該当インデックスから\texttt{currentBPM}・\texttt{pwmValue}・\texttt{RPM}をそれぞれ求める．\texttt{updateStatus}関数は，この\texttt{RPM}および\texttt{pwmValue}を基に，(\ref{eq:average})式に相当する計算によって\texttt{omega}と\texttt{V\_average}を算出する．両関数をコード\ref{lst:motor_steptonumber}に示す．

\begin{lstlisting}[caption={MotorControl::stepToNumber関数・updateStatus関数}, label={lst:motor_steptonumber}]
void MotorControl::stepToNumber(uint8_t stepNumber) {
    if (stepNumber < 1 || stepNumber > 5) return;
    currentBPM = bpmTable[stepNumber - 1];
    pwmValue   = pwmTable[stepNumber - 1];
    RPM        = rpmTable[stepNumber - 1];
}

void MotorControl::updateStatus() {
    omega     = 2.0 * PI * RPM / 60.0f;
    V_average = VCC * (pwmValue / 256.0f);
}
\end{lstlisting}

次に，\texttt{displayBPM}関数について説明する．この関数は，loop関数から受け取ったBPM段階番号（1〜5）を\texttt{bpmTable}[]で参照して実際のBPM値に変換したうえで各桁ごとに分割し，\texttt{drawDigit}()を用いてフレームバッファに描画する．そして，uint32\_t[3]形式にビットパックした後，matrix.loadFrame()で描画を行う．\texttt{displayBPM}関数をコード\ref{lst:disp_displaybpm}に示す．

\begin{lstlisting}[caption={displayBPM関数}, label={lst:disp_displaybpm}]
void displayBPM(uint8_t stepNumber) {
    if (stepNumber < 1 || stepNumber > 5) return;
    uint8_t bpm = bpmTable[stepNumber - 1];

    memset(frameBuffer, 0, sizeof(frameBuffer));

    int digits[3];
    int numDigits;
    if (bpm >= 100) {
        numDigits = 3;
        digits[0] = bpm / 100;
        digits[1] = (bpm / 10) % 10;
        digits[2] = bpm % 10;
    } else if (bpm >= 10) {
        numDigits = 2;
        digits[0] = bpm / 10;
        digits[1] = bpm % 10;
    } else {
        numDigits = 1;
        digits[0] = bpm;
    }

    int totalWidth = numDigits * FONT_WIDTH + (numDigits - 1) * 1;
    int startX     = (MATRIX_COLS - totalWidth) / 2;

    for (int i = 0; i < numDigits; i++) {
        drawDigit(digits[i], startX + i * (FONT_WIDTH + 1));
    }

    uint32_t bitmap[3] = {0, 0, 0};
    for (int row = 0; row < MATRIX_ROWS; row++) {
        for (int col = 0; col < MATRIX_COLS; col++) {
            if (frameBuffer[row][col]) {
                int n = row * MATRIX_COLS + col;
                bitmap[n / 32] |= (1UL << (31 - (n % 32)));
            }
        }
    }
    matrix.loadFrame(bitmap);
}
\end{lstlisting}

次に，\texttt{drawDigit}関数について説明する．この関数は，引数の数字が0から9の範囲内であるかを確認した後，縦方向の中央寄せオフセットを算出し，独自フォント配列から該当する数字のドットパターンを1ドットずつ読み取ってフレームバッファの指定位置に書き込む．\texttt{drawDigit}関数をコード\ref{lst:disp_drawdigit}に示す．

\begin{lstlisting}[caption={drawDigit関数}, label={lst:disp_drawdigit}]
void drawDigit(int digit, int x_offset) {
    if (digit < 0 || digit > 9) return;
    const int y_offset = (MATRIX_ROWS - FONT_HEIGHT) / 2;
    for (int y = 0; y < FONT_HEIGHT; y++) {
        for (int x = 0; x < FONT_WIDTH; x++) {
            int col = x_offset + x;
            int row = y_offset + y;
            if (col >= 0 && col < MATRIX_COLS && row >= 0 && row < MATRIX_ROWS) {
                frameBuffer[row][col] = font3x5[digit][y * FONT_WIDTH + x];
            }
        }
    }
}
\end{lstlisting}

次に，\texttt{LaserDetector}クラスのupdate関数について説明する．この関数は，\texttt{detectLight}関数によってパルスの立ち上がりが検知され，かつ前回検知から\texttt{DEBOUNCE\_MS}（200 ms）以上が経過している場合にのみ，trueを返してinterval（前回検知時刻との差）を書き込む．update関数をコード\ref{lst:laser_update}に示す．

\begin{lstlisting}[caption={LaserDetector::update関数}, label={lst:laser_update}]
bool update(int cdsValue, unsigned long nowMs, unsigned long &intervalOut) {
    if (calibrationStartMs == 0) calibrationStartMs = nowMs;
    if (!detectLight(cdsValue, nowMs)) return false;
    if (nowMs - lastDetectTime < DEBOUNCE_MS) return false;

    intervalOut = (lastDetectTime != 0) ? (nowMs - lastDetectTime) : 0;
    bool hasInterval = (lastDetectTime != 0);
    lastDetectTime = nowMs;
    return hasInterval;
}
\end{lstlisting}

最後に，\texttt{detectLight}関数について説明する．この関数は，暗状態の推定値である\texttt{baseline}を継続的に追従させながら，値が\texttt{baseline}+\texttt{CDS\_MIN\_DELTA}相当の\texttt{onThreshold}を上回った瞬間をパルスの立ち上がりとして検知する状態機械である．起動直後は\texttt{startupCalibrated}フラグがfalseの間，\texttt{CDS\_STARTUP\_CALIBRATION\_MS}（1秒）をかけて最も暗い値を\texttt{baseline}の初期値として探索し，誤検知を防止する．また，キャリブレーション完了時点でレーザーが既に照射状態であった場合は，\texttt{waitingForRelease}フラグによって一度非照射状態に戻るまで検知を保留する．パルスの立ち下がり（照射終了）を検知すると\texttt{registerPeak}関数を呼び出し，しきい値を実測値に基づいて更新する．\texttt{detectLight}関数をコード\ref{lst:laser_detectlight}に示す．

\begin{lstlisting}[caption={LaserDetector::detectLight関数}, label={lst:laser_detectlight}]
bool detectLight(int v, unsigned long nowMs) {
    if (!baselineReady) {
      baseline = v;
      startupMin = v;
      baselineReady = true;
      updateFallbackThresholds();
    }

    if (!startupCalibrated) {
      if (v < startupMin) startupMin = v;
      baseline = startupMin;
      updateFallbackThresholds();
      if (nowMs - calibrationStartMs < CDS_STARTUP_CALIBRATION_MS) return false;
      startupCalibrated = true;
      waitingForRelease = (v >= onThreshold);
      releaseThreshold = (baseline > 1023 - CDS_MIN_DELTA) ? baseline - CDS_MIN_DELTA : offThreshold;
      return false;
    }

    if (waitingForRelease) {
      if (v <= releaseThreshold) {
        baseline = v;
        updateFallbackThresholds();
        waitingForRelease = false;
      }
      return false;
    }

    if (!laserOn) {
      if (v < baseline) baseline = v;
      else baseline = (baseline * 31 + v) / 32;
      if (!calibrated) updateFallbackThresholds();
    }

    if (!laserOn && v >= onThreshold) {
      laserOn = true;
      pulsePeak = v;
      return true;
    }

    if (laserOn) {
      if (v > pulsePeak) pulsePeak = v;
      if (v <= offThreshold) {
        laserOn = false;
        registerPeak(pulsePeak);
      }
    }
    return false;
}
\end{lstlisting}

\begin{lstlisting}[caption={DataUtils::GetProfileForPitch関数（要部）}, label={lst:gakki_getprofile}]
float[][] GetProfileForPitch(float pitch, float[][][] lut, int baseMidiNote) {
  float originalPitch = pitch;
  float maxMidiNote = baseMidiNote + lut.length - 1;
  float searchPitch = constrain(pitch, baseMidiNote, maxMidiNote);

  int targetIndex = round(searchPitch) - baseMidiNote;
  targetIndex = constrain(targetIndex, 0, lut.length - 1);

  // targetIndexがnull（データ欠損）の場合は、最も近い有効なインデックスを探索する
  int finalIndex = targetIndex;
  // (探索処理は省略。詳細は付録のプログラム全文を参照)

  float[][] sourceProfile = lut[finalIndex];
  int numPeaks = sourceProfile.length;
  float[][] result = new float[numPeaks][2];

  // 流用元サンプルの基準MIDIノート番号を逆算
  float sourceMidi = finalIndex + baseMidiNote;
  // 要求ピッチと流用元との半音差から、周波数の倍率を算出
  float pitchShiftFactor = pow(2.0f, (originalPitch - sourceMidi) / 12.0f);

  for (int h = 0; h < numPeaks; h++) {
    result[h][0] = sourceProfile[h][0] * pitchShiftFactor; // 実測周波数構造をそのままスケーリング
    result[h][1] = sourceProfile[h][1]; // 振幅はそのままコピー
  }
  return result;
}
\end{lstlisting}

次に，\texttt{GetDynamicProfile}関数について説明する．この関数は，まずpp/mf/ffの3つの強弱プロファイルを\texttt{GetProfileForPitch}関数で取得したうえで，ベロシティを0〜1に正規化し，あらかじめ定めた3つの閾値（32/80/112 を127で除した値）と比較して，隣接する2つの強弱のうちベロシティに近い方のプロファイル形状を採用する．続いて，振幅0.05未満の微小なピークを除去したうえで，採用した各ピークの振幅の2乗和（エネルギー）に対する目標音量の比からゲインを算出し，全ピークへ一括で乗算することで最終的な音量を決定する．\texttt{GetDynamicProfile}関数の要部をコード\ref{lst:gakki_getdynamic}に示す．

\begin{lstlisting}[caption={DataUtils::GetDynamicProfile関数（要部）}, label={lst:gakki_getdynamic}]
float[][] GetDynamicProfile(float pitch, float velocity, String type, int baseMidiNote, float basePower) {
  float[][] profilePP, profileMF, profileFF;
  // switch(type)によりPP/MF/FFの各LUTからGetProfileForPitchで取得（詳細略）

  float normVel = constrain(velocity, 0, 127) / 127.0f;
  float thresholdPP = 32.0f / 127.0f;
  float thresholdMF = 80.0f / 127.0f;
  float thresholdFF = 112.0f / 127.0f;

  float[][] baseProfile;
  float t = 0;
  if (normVel <= thresholdPP) {
    baseProfile = profilePP;
  } else if (normVel <= thresholdMF) {
    t = map(normVel, thresholdPP, thresholdMF, 0.0f, 1.0f);
    baseProfile = (t < 0.5f) ? profilePP : profileMF;
  } else if (normVel <= thresholdFF) {
    t = map(normVel, thresholdMF, thresholdFF, 0.0f, 1.0f);
    baseProfile = (t < 0.5f) ? profileMF : profileFF;
  } else {
    baseProfile = profileFF;
  }

  int numPeaks = baseProfile.length;
  float ampThreshold = 0.05f;
  int validPeakCount = 0;
  float energy = 0;
  float[][] finalProfile = new float[numPeaks][2]; // 実際は有効数分で確保

  for (int h = 0; h < numPeaks; h++) {
    if (baseProfile[h][1] < ampThreshold) continue; // 微小ピークは除去
    finalProfile[validPeakCount][0] = baseProfile[h][0];
    finalProfile[validPeakCount][1] = baseProfile[h][1];
    energy += baseProfile[h][1] * baseProfile[h][1];
    validPeakCount++;
  }

  float targetVolume = basePower * pow(normVel, 0.9f);
  float gain = targetVolume / sqrt(energy + 1e-9f);
  for (int i = 0; i < validPeakCount; i++) {
    finalProfile[i][1] *= gain; // エネルギー正規化ゲインを適用
  }
  return finalProfile;
}

\begin{lstlisting}[caption={AddReverb::uGenerate関数}, label={lst:gakki_reverb}]
protected void uGenerate(float[] channels) {
  float[] inputs = audio.getLastValues();
  float inL = inputs[0];
  float inR = (inputs.length > 1) ? inputs[1] : inL;

  historyBufferL[bufferIndex] = inL;
  historyBufferR[bufferIndex] = inR;

  float outL = 0;
  float outR = 0;
  for (int j = 0; j < kernelSize; j++) {
    int idx = (bufferIndex - j + kernelSize) % kernelSize;
    outL += historyBufferL[idx] * impulseResponse[j];
    outR += historyBufferR[idx] * impulseResponse[j];
  }

  bufferIndex = (bufferIndex + 1) % kernelSize;

  if (channels.length == 1) {
    channels[0] = inL + outL;
  } else if (channels.length >= 2) {
    channels[0] = inL + outL;
    channels[1] = inR + outR;
  }
}
\end{lstlisting}

  float safeDur = dur + 0.5f;

  for(int i = 0; i < numHarmonics; i++) {

次に，\texttt{createInstrumentOscillators}関数について説明する．この関数は，指定された楽器のLUTプロファイルを振幅の大きい順にソートしたうえで上限本数（maxPeaks）まで選別し，周波数の低い順に並べ直してからOscilとして生成する．これにより，計算負荷を抑えつつ音色に対する寄与の大きい成分を優先的に採用している．\texttt{createInstrumentOscillators}関数の要部をコード\ref{lst:gakki_strings_create}に示す．

\begin{lstlisting}[caption={StringsInstrument::createInstrumentOscillators関数（要部）}, label={lst:gakki_strings_create}]
private void createInstrumentOscillators(final float[][] profile, float blendRatio, int maxPeaks,
    float volFactor, float globalVibSpeed, float fmDepthCents, Summer mixer,
    float startGainFactor, float endGainFactor) {
  if (profile == null || profile.length == 0) return;

  // 振幅の大きい順にインデックスをソートし、上位limitPeaks個を抽出（詳細は付録参照）
  // その後、周波数の低い順に並べ直す

  for (int h = 0; h < limitPeaks; h++) {
    if (totalActiveOscils >= maxTotalOscils) break;

    float targetFreq = filteredProfile[h][0];
    float rawAmp     = filteredProfile[h][1];
    if (targetFreq > 14000.0f) continue;

    // 7000Hz〜17000Hzにかけて振幅を滑らかに減衰させる高域フィルター
    if (targetFreq > 7000.0f) {
      float filterFactor = map(targetFreq, 7000.0f, 17000.0f, 1.0f, 0.0f);
      rawAmp *= constrain(filterFactor, 0.0f, 1.0f);
    }

    float baseAmp = rawAmp * volFactor * blendRatio;
    int idx = totalActiveOscils;
    startAmps[idx] = baseAmp * startGainFactor;
    endAmps[idx]   = baseAmp * endGainFactor;

    oscils[idx] = new Oscil(targetFreq, 0.0f, Waves.SINE);
    oscils[idx].setPhase(random(1.0f));
    oscils[idx].patch(mixer);
    totalActiveOscils++;
  }
}
\end{lstlisting}

\paragraph{ピアノ（\texttt{PianoInstrument}）}
次に，ピアノの音色合成について説明する．\texttt{PianoInstrument}クラスは，1つの音に対して2本の弦をわずかにデチューン（周波数をずらす）して重ねる「デュアル・ストリング構造」により，時間が経つにつれて自然に生じる音のうなり（Beat）を再現している点が特徴である．また，実測データ（LUT）が存在しない倍音・音域については，ピアノの物理特性の傾向を数式化した近似モデルで補完するハイブリッド方式を採用している．\texttt{PianoInstrument}クラスで使用する主な変数・関数の仕様を表\ref{table:gakki_piano}に示す．

\begin{table}[H]

    \centering

    \textbf{名称} & \textbf{説明}\\
    \hline
    \texttt{masterEnv}（変数） & ダンパー（離鍵時のミュート）の挙動を表す全体エンベロープ\\
    \hline
    \texttt{hammerEnv}（変数） & ハンマーが弦を叩く瞬間のノイズ用エンベロープ\\
    \hline

以下では，デュアル・ストリング構造の構築部分について説明する．各倍音について，アタックの芯となるレイヤーA（\texttt{coreOsc}）と，時間差で立ち上がる共鳴弦のレイヤーB（\texttt{resOsc}）の2層を生成する．レイヤーBはレイヤーAよりわずかに周波数をずらし（\texttt{wobbleRate}分のデチューン），\texttt{buildUpTime}秒かけてゆっくり音量を上げることで，芯の音と干渉して自然なうなりを生む．デュアル・ストリング構造の構築部分をコード\ref{lst:gakki_piano_dual}に示す．

\begin{lstlisting}[caption={PianoInstrumentコンストラクタ（デュアル・ストリング構造）}, label={lst:gakki_piano_dual}]
// レイヤーA：アタックの芯（Dry弦）
Oscil coreOsc = new Oscil(targetFreq, amp, Waves.SINE);
coreOsc.setPhase(random(0.0f, 0.1f));
Damp coreDamp = new Damp(0.001f, decayTime);
coreOsc.patch(coreDamp).patch(mixer);
damps.add(coreDamp);

// レイヤーB：時間差で来る響き（共鳴弦）
float reverbAmp = amp * wobbleDepth;
if (reverbAmp > 0.0001f && wobbleRate > 0.0f) {
  // 周波数をわずかにズラす（Detune）ことで、芯の弦と干渉して自然な「うなり(Beat)」を生む
  Oscil resOsc = new Oscil(targetFreq + wobbleRate, reverbAmp, Waves.SINE);
  Damp resDamp = new Damp(buildUpTime, decayTime);
  resOsc.patch(resDamp).patch(mixer);
  damps.add(resDamp);
}
\end{lstlisting}

続いて，ハンマーの打撃ノイズについて説明する．音程の高低に応じてフィルターのカットオフを変化させることで，高音の鍵盤ほど硬い「カチッ」としたノイズになるよう調整している．ハンマーノイズ部分をコード\ref{lst:gakki_piano_hammer}に示す．

\begin{lstlisting}[caption={PianoInstrumentコンストラクタ（ハンマーノイズ部分）}, label={lst:gakki_piano_hammer}]
float hammerVol = masterVol * 0.003f * normVel;
Noise hammerNoise = new Noise(hammerVol, Noise.Tint.WHITE);

float hammerCutoff = map(midiNote, 21, 108, 600f, 4000f);
MoogFilter hammerFilter = new MoogFilter(hammerCutoff, 0.1f);
hammerFilter.type = MoogFilter.Type.LP;

hammerEnv = new ADSR(1.0f, 0.001f, 0.02f, 0.0f, 0.01f);
hammerNoise.patch(hammerFilter).patch(hammerEnv);
\end{lstlisting}

\paragraph{ドラム（\texttt{KickInstrument}・\texttt{SnareInstrument}・\texttt{HiHatInstrument}）}
次に，ドラムの音色合成について説明する．ドラムはフルート等の旋律楽器とは異なり，Instrumentクラスをキック・スネア・ハイハットの3種類（および過去に試作された\texttt{SnareInstrumentOld}・\texttt{HiHatInstrumentOld}の旧版，未使用の\texttt{CymbalInstrument}）に分けて実装している．いずれも短時間で減衰する打撃音であるため，全体の出力は\texttt{shortOut}バスへパッチされる．3種の主要な変数・関数の仕様を表\ref{table:gakki_drum}に示す．

以下では，キックのピッチスイープと，スネアの胴鳴りパートについて，実際のコードとともに説明する．まず，\texttt{KickInstrument}のピッチスイープについて説明する．各周波数成分について，Lineを用いて0.01秒かけて「本来の周波数の1.5倍」から「本来の周波数」へ直線的に下げることで，太鼓の膜が叩かれた瞬間にピッチが下がっていく物理的な挙動を再現している．該当部分をコード\ref{lst:gakki_kick}に示す．

\begin{lstlisting}[caption={KickInstrumentコンストラクタ（ピッチスイープ部分）}, label={lst:gakki_kick}]
for (int i = 0; i < numComponents; i++) {
  if (kickLUT[i] == null || kickLUT[i].length < 3) continue;

  float freq = kickLUT[i][0] * random(0.95f, 1.05f);
  float mag = kickLUT[i][1];
  float decayTime = kickLUT[i][2];
  float amp = (baseAmp * mag) / numComponents;

  tones[i] = new Oscil(freq, amp, Waves.SINE);
  harmonicEnvs[i] = new ADSR(1.0f, 0.001f, decayTime*0.5f, 0.0f, 0.1f);

  // ピッチスイープ：1.5倍の高さから本来の周波数へ急降下させる
  pitchSweeps[i] = new Line(0.01f, freq * 1.5f, freq);
  pitchSweeps[i].patch(tones[i].frequency);

  tones[i].patch(harmonicEnvs[i]);
  harmonicEnvs[i].patch(mixer);
}
\end{lstlisting}

次に，\texttt{SnareInstrument}の胴鳴りパートについて説明する．発音の瞬間に約3倍の周波数から本来の胴鳴り周波数（172.3~Hz）へ急降下させるピッチエンベロープにより，スネアドラム特有のアタック感を表現している．該当部分をコード\ref{lst:gakki_snare}に示す．

\begin{lstlisting}[caption={SnareInstrumentコンストラクタ（胴鳴りパート）}, label={lst:gakki_snare}]
float bodyFreq      = 172.3f * random(0.99f, 1.01f); // 実測データの最強ピーク
float bodyPitchMod  = 3.0f;   // アタック時は約516Hzから172.3Hzへ急降下
float bodySweepTime = 0.025f;
float bodyDecay     = 0.07f;
float bodyVolRatio  = 0.63f * sinSet;

bodyOsc = new Oscil(bodyFreq, baseAmp * bodyVolRatio, Waves.SINE);
bodyPitchEnv = new Line(bodySweepTime, bodyFreq * bodyPitchMod, bodyFreq);
bodyPitchEnv.patch(bodyOsc.frequency);
bodyAmpEnv = new ADSR(1.0f, 0.001f, bodyDecay, 0.0f, 0.05f);
bodyOsc.patch(bodyAmpEnv).patch(mixer);
\end{lstlisting}

\paragraph{ホルンとトランペット（\texttt{HornInstrument}・\texttt{TrumpetInstrument}）}
最後に，ホルンおよびトランペットの音色合成について説明する．両クラスは，ハッカソン第11回時点で追加された金管楽器であり，事前課題の報告の通り，既存の\texttt{FluteInstrument}クラスの加算合成・ビブラート・息ノイズの構造をそのまま流用したうえで，\texttt{KickInstrument}で用いていたアタック時のピッチエンベロープ機能を新たに付加して作成されている．\texttt{HornInstrument}と\texttt{TrumpetInstrument}は，基準MIDIノートや各種パラメータの数値が異なるのみで，クラス構造自体は同一である．両クラスで使用する主な変数・関数の仕様を表\ref{table:gakki_horn}に示す．

\begin{table}[H]
    \caption{\texttt{HornInstrument}・\texttt{TrumpetInstrument}クラスで使用する主な変数・関数の仕様一覧}
    \centering
    \label{table:gakki_horn}
    \begin{tabular}{p{4.3cm}p{9.7cm}}
    \hline
    \textbf{名称} & \textbf{説明}\\
    \hline

以下では，両クラスに共通するアタック時のピッチエンベロープ機能について，\texttt{HornInstrument}のnoteOn関数を例に説明する．発音直後，各倍音の周波数を本来値より一時的に高く（ホルンでは\texttt{pitchMod}=0.05，すなわち5\%増しから）設定し，\texttt{sweepTime}秒（ホルンでは0.12秒）かけて本来の周波数へ直線的に戻すことで，金管楽器特有の「音の頭が一瞬上ずってから定まる」挙動を再現している．該当部分をコード\ref{lst:gakki_horn_pitch}に示す．なお，トランペットでは同じ構造に対して\texttt{pitchMod}=0.03，\texttt{sweepTime}=0.07秒という異なる数値が用いられている．

\begin{lstlisting}[caption={HornInstrument::noteOn関数（ピッチエンベロープ部分）}, label={lst:gakki_horn_pitch}]
float sweepTime = 0.12f; // 変化にかかる時間
float pitchMod  = 0.05f; // 本来の周波数に対する上乗せ割合

for(int i = 0; i < numHarmonics; i++) {
  harmonicEnvs[i].noteOn();
  ampLines[i].activate(safeDur, startAmps[i], endAmps[i]);
  if (wobbleLines[i] != null) {
    float factor = wobbleFactors[i];
    wobbleLines[i].activate(safeDur, startAmps[i] * factor, endAmps[i] * factor);
  }

  // アタック時のピッチエンベロープ（周波数の急降下）
  if (pitchEnvLines[i] != null) {
    float baseFreq = targetFreqs[i];
    float startFreq = baseFreq * (1.0f + pitchMod); // 本来の周波数にpitchMod分を上乗せした値からスタート
    pitchEnvLines[i].activate(sweepTime, startFreq, baseFreq); // baseFreqへ一直線に下げる
  }
}
\end{lstlisting}
